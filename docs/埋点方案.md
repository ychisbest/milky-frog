# 奶蛙割草 · 数据埋点方案

代码：`assets/scripts/Analytics.ts`（`Analytics.track(事件ID, 字段)`）。
微信走 `wx.reportEvent`（基础库 ≥ 2.14.4），抖音走 `tt.reportAnalytics`；浏览器预览和测试中不上报，`Analytics.debug = true` 时在控制台打印。

## 一、后台配置（上线前必做）

**事件和字段必须先在后台登记，未登记的上报会被丢弃。**

微信：登录 [We 分析](https://wedata.weixin.qq.com) → 选择小游戏 → 「自定义分析 → 事件管理 → 新建事件」，按下表逐个填写事件 ID（英文名）和字段（字段名 + 类型）。可以在开发者工具 / 真机调试里点几下，后台「实时数据」能看到上报即为配置正确。

抖音：开发者后台「数据 → 自定义事件」同样登记。

## 二、事件清单（23 个）

`字符串` / `数字` 是后台字段类型，选错会导致该字段为空。

| 事件 ID | 触发时机 | 字段 |
| --- | --- | --- |
| `launch` | 冷启动 | `scene` 数字 场景值 · `is_new` 数字 1=还没玩过一局 · `runs` 数字 累计局数 · `day_n` 数字 距首次游玩天数（0=首日） · `ver` 字符串 版本号 |
| `app_show` | 从后台回到游戏（热启动） | `scene` 数字 · `runs` 数字 |
| `app_hide` | 切到后台 / 关闭 | `state` 字符串 当时界面 · `run_no` 数字 · `run_sec` 数字 局内已进行秒数（不在局内为 0） |
| `privacy` | 隐私弹窗点选 | `agree` 数字 1=同意 0=不同意 |
| `tut_step` | 首局新手引导推进到第 N 步 | `step` 数字 1~6（6=引导全部完成） · `sec` 数字 本局第几秒 |
| `run_start` | 开局（含每日挑战） | `run_no` 数字 第几局 · `char` 字符串 角色 · `stage` 字符串 地图 · `mode` 字符串 normal/endless/nightmare/daily · `day_n` 数字 |
| `run_end` | 结算 | 同 `run_start` 的字段，另加：`result` 字符串 win/lose/quit · `time_sec` 数字 存活秒数 · `level` 数字 · `kills` 数字 · `boss_kills` 数字 · `evolved` 数字 进化武器数 · `revived` 数字 1=看广告复活过 · `gold` 数字 本局所得金币 · `achv` 数字 新成就数 |
| `result_next` | 离开结算页 | `next` 字符串 replay/menu · `run_no` 数字 · `inter` 数字 1=尝试弹插屏 |
| `ad_reward` | 激励视频结束 | `place` 字符串 revive/gold/reroll/chest/blessing/signin · `result` 字符串 ok/skipped/error · `run_no` 数字 |
| `share` | 点分享 | `from` 字符串 result=结算页按钮 / daily=每日挑战结算 / menu=右上角菜单 · `won` 数字 |
| `shop_buy` | 购买永久强化 | `item` 字符串 · `level` 数字 买到第几级 · `cost` 数字 · `runs` 数字 |
| `char_unlock` | 金币解锁角色 | `char` 字符串 · `cost` 数字 · `runs` 数字 |
| `sign_in` | 签到 | `day` 数字 本轮第几天（1~7） · `mul` 数字 1=普通 2=看视频双倍 · `day_n` 数字 |
| `challenge_open` | 点开带战绩的分享卡片 | `daily` 数字 1=每日挑战卡片 · `warm` 数字 1=热启动 |
| `challenge_accept` | 点「接受挑战」 | `daily` 数字 1=进入同一每日挑战 · `runs` 数字 |
| `challenge_result` | 好友挑战局结算 | `beat` 数字 1=超过好友 · `daily` 数字 · `time_sec` 数字 |
| `rank_open` | 打开好友排行 | `from` 字符串 menu/daily · `kind` 字符串 best/daily |
| `club_tap` | 点游戏圈按钮 | `runs` 数字 |
| `add_tip` | 关闭「添加到我的小程序」提示 | `wins` 数字 |
| `unlock` | 新手渐进解锁开放新功能 | `runs` 数字 · `n` 数字 本次开放个数 |
| `update` | 版本更新 | `action` 字符串 ready/apply/later/failed |
| `cloud_sync` | 云存档启动同步 | `action` 字符串 pull=云端覆盖本地 / keep=保留本地 / new=首次上传 / error=失败 · `runs` 数字 |

> 引导步骤：1 自动攻击 → 2 捡宝石 → 3 三选一 → 4 生存目标 → 5 Boss 预警 → 6 完成（第 0 步"拖动移动"在开局即进入，不单独上报）。
> 玩家在局内直接划走小游戏时不会结算，这种情况看 `app_hide` 的 `run_sec`。

## 三、上线后先看的 6 张表

| 问题 | 怎么看 | 参考目标 |
| --- | --- | --- |
| **新手漏斗**：在哪一步流失 | `launch(is_new=1)` → `privacy(agree=1)` → `tut_step` 1~6 → `run_end(run_no=1)` → `run_start(run_no=2)`，按人数做漏斗 | 首局 → 第 2 局 ≥ 60% |
| **首局体验**：首局在第几分钟结束 | `run_end(run_no=1)` 的 `time_sec` 分布、`result` 占比；`app_hide` 中 `run_no=1` 且 `run_sec>0` 的人（直接划走） | 峰值 6–12 分钟，quit + 直接划走 < 15% |
| **留存** | `launch` 按 `day_n` 分组的人数（day_n=1 / day0 新增 ≈ 次留），配合后台自带留存报表 | 次留 ≥ 35% |
| **难度**：倒在哪 | `run_end` 按 `run_no`（1/2/3/5/10）看 `result=win` 占比和 `boss_kills` | 对照 `数值设计.md`：首局 25–35%，第 3 局 ≈ 50% |
| **广告**：哪个位置最受欢迎 | `ad_reward` 按 `place` 分组的次数与 `result=ok` 占比；`run_end` 中 `revived=1` 的占比 | 人均激励视频 ≥ 3 / 日 |
| **好友挑战裂变** | `share` → `challenge_open` → `challenge_accept` → `challenge_result`；`launch(scene=1007/1008, is_new=1)` 即分享带来的新用户 | 每 10 次分享带来 ≥ 1 个新用户 |
| **来源与分享** | `launch` / `app_show` 按 `scene` 分组（1007 单聊卡片、1008 群聊卡片、1154 朋友圈、1005/1006 搜索、1089 我的小程序、1001 下拉）；`share` 按 `from` 分组 | 分享回流（1007+1008）占新增的比例逐周上升 |

另外：`result_next` 中 `replay` 的比例就是"再来一局率"；`shop_buy` / `char_unlock` 的 `runs` 能看出玩家第几局开始养成。

## 四、新增埋点的规则

- 事件 ID 与字段名只用**小写字母、数字、下划线**，字母开头（回归测试会检查）
- 字段值只用字符串或数字，不传对象 / 数组 / 布尔（布尔用 0/1）
- 不上报任何个人信息（昵称、头像、openid 等），隐私指引无需改动
- 新增事件后：后台登记 → 更新本文件第二节 → `tools/tests/run.sh`
