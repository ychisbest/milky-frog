## 下次直接这样做

1. 确认成片、横封面、竖封面和各平台文案齐备；先限制快手话题为 **4 个以内**。
2. 优先检查本机正在运行的 `ego.exe`。本次程序路径为 `C:\Program Files\Citro Labs\ego lite\Application\ego.exe`，没有同名 Linux 命令，也没有找到 egolite 插件。不要再次花时间全盘寻找 CLI 或安装插件。
3. 使用现有登录态，为发布打开独立窗口；记录本次窗口句柄，后续操作均带 `--handle`。句柄每次重新获取，不能复用本文历史值。不要操作原有任务窗口。
4. 上传视频，利用上传时间准备其他平台的文案和表单；涉及原生文件对话框、剪贴板和键盘的操作顺序执行，避免抢焦点。
5. 按实际顺序填写：文案 → 封面 → AI 声明 → 可见范围/立即发布 → 检查 → 提交。上传完成、正文增高、封面应用后，重新读取控件位置。
6. 提交只执行一次。遇到无响应先检查按钮状态、成功提示、作品列表和当前 URL，不能连续盲点。取得成功提示后再核对作品标题、时长与状态，最后保存链接和发布记录。

## 这次卡在哪里

| 卡点 | 本次表现 | 下次处理 |
|---|---|---|
| 工具入口发现耗时 | 没有 `egolite` CLI，也没有连接器；实际是 Windows 上运行的 Chromium 浏览器 | 直接查 `Get-Process ego`，使用 Windows UI Automation 操作现有窗口；只有入口失效时才扩大搜索 |
| 没有 CDP 接口 | 运行中的 ego lite 未开放远程调试端口 | 已有 UIA 方式可用，不为接入 CDP 重启用户浏览器 |
| 多窗口和焦点混淆 | 最初取“第一个 ego 窗口”，读到了原有任务；后续还出现标题、地址栏与页面树不一致 | 每个平台绑定独立 HWND；聚焦后核对 URL 和页面标题，再操作；异常时重新取页面树，不沿用旧结果 |
| 原生文件对话框控件不完整 | UIA 没列出“文件名/打开”控件；`Alt+N` 和粘贴路径没有稳定完成选文件 | 先截图确认对话框和目录，再选择真实文件并打开；进入交付目录后，视频筛选只剩一份 MP4，图片筛选按文件名选横/竖封面 |
| WSL 文件路径 | Windows 浏览器不能直接使用 `/home/...` | 用 `wslpath -w` 得到 `\\wsl.localhost\Ubuntu-26.04\...`；本次可直接上传，无需额外复制 80 MB 视频 |
| 页面布局会变化 | 上传完成新增章节，正文填入后推荐话题出现，导致后续坐标变化 | 优先按名称和控件类型定位；仅在原生对话框等必要场合用截图坐标。提交前重新检查声明和封面是否真正生效 |
| 文本不是按钮 | B 站“立即投稿”为 Text，鼠标点击没有稳定提交；其直接父级 Group 支持 `InvokePattern`，调用后成功 | 检查目标及直接父级的 `GetSupportedPatterns()`；优先语义调用。现有脚本 `invoke` 不会自动向父级查找，本次父级调用是单独执行的 |
| 下拉项漏读 | 只筛 Button/Edit/Text 时看不到 B 站创作声明选项和投稿链接 | 页面检查同时包含 `ListItem` 和 `Hyperlink`；脚本已补齐 |
| 下拉菜单保留滚动位置 | B 站分区默认 vlog，菜单打开后停在底部 | 在下拉菜单内滚动，待滚动稳定后重新读取选项；本次选“游戏”，不是默认 vlog |
| 平台话题限制 | 快手粘贴 5 个话题提示“最多只能添加4个话题”，正文未成功填入 | 快手预先生成 4 话题版本；不能只看粘贴动作返回成功，要确认正文实际存在 |
| 标签不能任意创建 | B 站 `CocosCreator` 提示为话题专用，不允许自定义添加 | 删除未创建的输入，保留已成功创建的 7 个相关标签；不为非必需标签反复试错 |
| 异步状态误判 | 上传/封面应用/作品列表刷新存在延迟；“操作返回成功”不等于最终生效 | 用“上传完成”“封面应用成功”“作者声明”“作品标题+时长”等状态作为下一步条件；不要在加载中连续点下一步 |
| 过度输出和截图 | 大量重复打印浏览器导航、书签和旧页面信息 | 优先读取目标 Document，按任务关键词过滤，只输出相关表单和状态；截图只用于定位失败、封面检查、最终证据 |
| PowerShell 引号转义 | 直接在 shell 内嵌 C# / 多层引号曾报错 | 复用脚本的 UTF-16LE `-EncodedCommand`；不临时拼多层转义命令 |
